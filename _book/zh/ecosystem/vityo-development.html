Vityo 协作指南

本页说明 Vityo 仓库的开发共识与协作指引。

Vityo 作为 Styio 的专属 IDE、运行视窗与 AI 协作前端，旨在为用户提供直观的代码编写与执行体验。

演进阶段

目前 Vityo 正处于 架构引导（Architecture Bootstrap） 阶段。在这一阶段，我们倾向于 文档先行（Docs-first） 的协作模式：

  1. 对齐规格：优先在 docs/ 目录下明确产品规格、系统架构与平台边界。
  2. 共识决策：涉及重大架构调整时，建议通过 ADR（架构决策记录）沉淀共识。
  3. 分阶段实现：在规格冻结后，逐步开展 UI 与后端逻辑的开发。

这种模式有助于我们在早期厘清复杂的平台策略与跨端交互。

Vityo 的核心职责

在生态协作中，Vityo 专注于以下领域：

  • 交互引擎：专属编辑器引擎、运行视图可视化及 AI 协作面板。
  • 主题与表现：视觉系统、UI 组件库及主题扩展。
  • 执行路由：管理不同平台（桌面、移动端、云端）的执行适配逻辑。
  • 模块宿主：支持功能模块的动态加载与分阶段更新。

协作中的解耦共识

为了维护编译器的语义权威，Vityo 与 styio 建立了以下协作共识：

  • 接口驱动：Vityo 倾向于消费编译器提供的标准公共接口（如 Token 范围、诊断载荷、运行事件流）。
  • 语义归位：语言的核心语义（如语法判定、类型推断）由 styio 定义。Vityo 专注于这些事实的呈现与交互。
  • 平滑协作：当 IDE 需要更深层次的语法分析能力时，建议通过增强编译器侧的 IDE Service 接口来实现。

平台执行策略建议

由于不同平台对 JIT 与 AOT 的限制不同，建议在开发中参考以下策略：

  • Desktop: 倾向于本地优先执行。
  • iOS: 倾向于云端执行主路径。
  • Android: 支持分阶段的本地执行适配。
  • Web: 侧重于轻量化查看与演示。

语法更新的同步节奏

当 styio 引入新语法特性时，Vityo 建议按以下面进行适配验证：

  1. 视觉呈现：更新语法高亮与 Token 分类逻辑。
  2. 辅助功能：同步 Snippet、补全提示及 Hover 信息。
  3. 质量反馈：优化新语法下的诊断范围定位。
  4. 导航适配：确保大纲视图（Outline）能正确识别新语法结构。

协作原则总结

  • 文档先行：规格与架构建议先于代码实现。
  • 契约协作：通过 styio-protocol 与稳定的 C ABI 暴露能力。
  • 需求上行：前端 IDE 的能力缺口建议转化为编译器的公共服务需求，共同提升生态基建。
